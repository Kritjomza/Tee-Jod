# Tee-Jod V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first KMUTT-themed LIFF website and LINE chatbot that display editable mock availability for four campus parking areas without reservations.

**Architecture:** One Next.js App Router project serves the public LIFF interface, demo admin interface, JSON endpoints, and LINE webhook. Supabase Postgres is the source of mock parking state; public reads use a publishable key and all writes use a server-only service-role client guarded by a demo PIN.

**Tech Stack:** Node.js 22, npm, Next.js App Router, React, TypeScript, Tailwind CSS, Supabase Postgres and `@supabase/supabase-js`, `@line/liff` 2.31.x, `@line/bot-sdk`, Zod, Vitest, Testing Library, Playwright, Vercel.

**Spec:** `docs/superpowers/specs/2026-09-18-tee-jod-v1-design.md`

## Global Constraints

- V1 displays availability only; it must not implement reservations, payments, vehicle tracking, or physical-sensor ingestion.
- Parking capacities are fixed at 60, 100, 200, and 366 for the four specified areas.
- Every user-facing availability screen must display “Prototype data — not real-time”.
- All visible dates use the `Asia/Bangkok` timezone.
- The UI must work at 320px width, meet WCAG AA contrast, expose textual status, and have visible keyboard focus.
- Use the image-derived palette `#F04400`, `#B83200`, `#161616`, `#FFF7F2`, and `#FFFFFF`; reserve green, amber, and red for status.
- Never expose `SUPABASE_SERVICE_ROLE_KEY`, `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, or `ADMIN_PIN` to the browser.
- Exact campus coordinates must be verified before navigation is enabled; unverified seed coordinates are `null`.
